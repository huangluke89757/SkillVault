# SkillVault v1.3.1 产品需求文档（PRD）

- 版本：v1.3.1
- 日期：2026-09-30
- 类型：体验优化（v1.3.0 翻译链路的急诊）
- 关联：`releases/v1.3.1/RELEASE-CHECKLIST.md`、v1.3.0 PRD

## 一、问题（为什么要改）

v1.3.0 上线后「中文简介」加载慢，实测定位到的根因与用户感知不符——**不是网络差，是实现方式拖慢**：

| 现象 | 实测数据 |
|---|---|
| MyMemory 单请求 | 冷启动 3.34s / 热请求 1.15s（可用） |
| Google gtx 兜底 | **http=000，10s 超时**（本机完全不可达） |
| 简介输入长度 | 上限 1200 字符 → 切成 3 块 |
| 分块执行方式 | **串行** await → 3 × (1.1~3.3s) = **3.4~10s** |
| 失败时 | 要先白等 10s 才看到降级提示 |
| 等待期间 UI | 卡片空白 + 转圈 |

## 二、目标与非目标

### 目标
- G1：把简介翻译耗时压到 **1–3s**（热请求 1.2s，冷启动 3.3s 属可接受）
- G2：失败时**立即**降级，不再空等
- G3：等待期间不空白，先显示英文原文

### 非目标
- 不更换翻译服务商（继续用 MyMemory 免费匿名端点）
- 不做本地模型翻译（离线方案排 v1.4）
- 不扩翻译范围（仍只翻标题 + 简介，不翻 SKILL.md 全文）

## 三、方案（四项改动）

| # | 改动 | 原理 |
|---|---|---|
| 1 | 简介截断到 ~300 字符（按句断开） | 请求数与耗时成正比；300 字符 = 1 次请求。简介本就只需前 1–2 句 |
| 2 | 分块改为**并发**（限并发 3） | 消除串行叠加；长文本最多 3 块同时进行 |
| 3 | 移除不可达的 Google gtx 兜底，超时 10s → 8s | 死端点只会制造 10s 空等 |
| 4 | 译文未就绪先铺英文原文 + 「翻译中」标注 | 感知耗时归零，失败也有内容可读 |

## 四、验收标准

- [ ] 300 字符简介：单次请求，热请求 ≈1.2s 出译文
- [ ] 断网/失败：立即显示英文原文并标注「翻译暂不可用」，无长时间空白
- [ ] 打开卡片即见英文原文，译文到达后自动替换
- [ ] `tsc --noEmit` 无错、构建通过
- [ ] 主包体积不回升（655 kB）

## 五、风险与取舍

| 风险 | 影响 | 处置 |
|---|---|---|
| 截断到 300 字符会丢信息 | 低 | 简介只需摘要；用户可切 EN 或看下方 SKILL.md 原文 |
| 单端点无兜底，MyMemory 挂了就整体不可用 | 中 | 已有降级 UI（显示英文原文）；v1.4 用本地模型彻底解决 |
| MyMemory 匿名配额（约 5000 词/天/IP） | 低 | 输入变短反而降低消耗；缓存 30 天 |

## 六、后续（v1.4）
- 本地模型翻译 `Xenova/opus-mt-en-zh`（首次下载 ~70MB），做成「在线 / 本地」可切换，彻底摆脱网络与配额
- 收藏列表页与「只看收藏」筛选
- 深链协议 `skillvault://install/<skillId>?agents=...`
